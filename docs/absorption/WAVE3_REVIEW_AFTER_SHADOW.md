# Wave 3 — Evidence Gates Re-Run After Phase 5

**Step 15.** Re-run of the four deferred Wave-3 candidates.
**Harness:** `scripts/wave3_gate_rerun.py` (reproducible; floors are constants)
**Result: 4 NO-GO. No floor was modified.**

---

## 1. Why this re-run cannot yet change anything

`WAVE3_EVIDENCE_REVIEW.md` §2 recorded the structural finding: four of five
Wave-3 gates need operational data that only Phase 5 produces. Phase 5 was
supposed to produce it.

**It did not, and could not.** Producing that data requires a deployed staging
instance receiving traffic against real providers. This environment has no
deployment target, no provider credentials, and no traffic. Phase 5 built the
substrate that *would* accumulate the evidence — shadow mode, the side-effect
boundary, provenance stamping, the campaign runners — but the substrate has not
been fed.

So the honest result is that the gates are **unchanged**, and the reason is
unchanged too. Nothing was lowered to manufacture movement.

### Candidate 2 deserves a specific note

`n_runs` moved from **0** to **1**. That is not progress toward the floor, and
treating it as progress would be the exact self-deception Phase 5 exists to
prevent. The single run was generated by **this repository's own test and
harness executions** — provenance `synthetic`. Rule 7 is explicit: synthetic
data may validate infrastructure and produce preliminary measurements, but it
is not operational evidence. A floor of n ≥ 200 exists to characterise *real
traffic*; 200 synthetic runs would satisfy it numerically and prove nothing.

The gate is therefore reported as NO-GO **on provenance as well as on count** —
and this is why the re-run harness prints a provenance column beside every n.

## 3. Finding W3R-1 — a published reproduction command silently stopped measuring what it claimed

`WAVE3_EVIDENCE_REVIEW.md` §1 publishes this as the reproduction for gates 1
and 3:

```
python -c "from olympus import modelgrade; print(len(modelgrade.cards()), modelgrade.enabled())"
#   0 False
```

Run today it prints **`4 False`**.

Nothing regressed and no card exists. `modelgrade.cards()` returns the whole
document — `{version, cards, conflicts, counts}` — so `len()` counts **four
dictionary keys**. The real card count is `cards()["counts"]["cards"]`, which
is **0**.

Severity is low (the verdict is unchanged) but the class of defect is not: a
documented reproduction command that reads as *"the floor is now four-fifths
met"* to anyone who runs it without reading the source. A reviewer checking
this repo's own published evidence would have been misled by the repo's own
instructions.

**Disposition.** `scripts/wave3_gate_rerun.py` measures `counts["cards"]`
explicitly and carries the explanation inline, so the correct measurement is
now the executable one rather than a prose correction that can drift again.
`WAVE3_EVIDENCE_REVIEW.md` is left unedited — it is the historical record of
what was measured at that time, and its verdict was right.

## 4. What each gate would actually need

None of these is buildable in this environment. They are listed so the next
phase has a work list rather than a mood.

| # | Needs | Blocked on |
|---|---|---|
| 1 | ≥ MIN_N graded outcomes per cell for a draft model AND a verifier, then a per-cell A/B on acceptance rate vs. the cost of the second call | provider credentials + traffic |
| 2 | ≥ 200 **real** runs with recorded tool/context coupling, Wilson CI ≤ 0.1 | traffic |
| 3 | a local runtime installed, plus an executed qualification campaign against it | a local model runtime |
| 4 | an observed provider-unavailability rate over a meaningful window | traffic + time |

Gate 4 additionally cannot be satisfied quickly even with traffic: an
unavailability rate is a rare-event measurement, and a week of clean staging
traffic may legitimately produce a rate of zero — which is itself a valid
result meaning *"mirroring is not worth its cost here"*.

## 5. Standing rule, restated

A passed gate authorizes an **implementation proposal**. It does not enable a
capability, and it does not authorize enabling one. All four candidates remain
`proposed` in `olympus/experiments.json`; none has been built, and the three
modules they would need (`localtier`, `draftverify`, `coalesce`) still do not
exist — the module budget was not spent on speculative code.
