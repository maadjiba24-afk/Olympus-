# Olympus Native Representations, Encoder Contracts and Baselines

**Seven representation candidates implemented and compared; the interfaces the
rest of Olympus depends on; nine baselines and the harness that scores them.**

- **Last updated:** 2026-07-28
- **Modules:** `native/interfaces.py`, `native/representations.py`,
  `native/baselines.py`, `native/benchmark.py`
- **Tests:** `tests/test_trading_native_repr.py` (72),
  `tests/test_trading_native_baselines.py` (55)
- **Companions:** `docs/OLYMPUS_MARKET_STATE_SCHEMA.md` (inputs),
  `docs/OLYMPUS_NATIVE_MODEL_STATUS.md` (the ledger)

> **Every number in this document comes from synthetic series generated by this
> repository.** They are evidence about the pipeline and about the relative
> behaviour of the candidates. They are not evidence about markets, and blocker
> B1 is why.

## 1. Encoder contracts

The rest of Olympus depends on `native/interfaces.py`, never on a concrete
encoder — the same bargain `forecast.Forecaster` makes one level up.

| Contract | What it fixes |
|---|---|
| `LatentSpec` | `(positions, d_model, sequential, emits_mask)`, declared **before** any forward pass, so a trunk can be built without running one |
| `EncoderMetadata` | Name, version, channels **in consumption order**, schema fingerprint, mask policy, measured parameter count. `identity()` is the hash two encoders must share to be interchangeable |
| `EncodedBatch` | Latent, optional per-position validity, optional codes, an opaque side channel. Refuses to contradict its own metadata |
| `MarketEncoder` | `encode(batch, mask=None) -> EncodedBatch`; `parameters_dict` / `load_parameters` |
| `Tokeniser` | `vocabulary_size`, `levels`, `tokenise`, `detokenise`, `utilisation` |
| `Reconstructor` | `reconstruct`, `reconstruction_error(..., mask=)` — masked positions **excluded**, never scored as zero |
| `TimeframeFusion` | `fuse(per_timeframe)`, with the timeframe order fixed at construction rather than read from mapping iteration order |
| `CrossAssetContext` | `contextualise(target, references)` |

Three properties are structural rather than conventional:

**The contracts are pure stdlib.** Importable with torch absent, because a
consumer that only wants to read a `LatentSpec` should not need a training
framework. `test_the_contracts_import_without_torch` asserts it.

**`MaskPolicy` has no `ZERO` member**, for the reason `schema.MissingPolicy` has
no zero-fill member. The four options are `REFUSE`, `LEARNED_ABSENT`,
`MASK_CHANNEL` and `EXCLUDE` — the last meaning the channel is dropped at
configuration time, which is why a runtime mask handed to an `EXCLUDE` encoder is
refused rather than ignored.

**Channel order is part of the identity.** An encoder trained on one order and
served on another is silently, totally wrong;
`test_encoder_metadata_identity_covers_more_than_the_name` checks that reordering
changes the hash.

## 2. The seven candidates

Each ships a `RepresentationCandidate` record — machine-readable, with every
field required non-empty, so `test_every_candidate_documents_all_eleven_required_facts`
can assert nothing ships undocumented. The full records are in
`representations.CANDIDATES`; this table is the summary.

| Candidate | Trainable components | Latent | Complexity | Tokenises |
|---|---|---|---|---|
| `continuous_patch` | projection `W (d×CP)`, bias, LayerNorm | `[B, T/P, d]` | `O(B·(T/P)·CP·d)`; params `CPd + 3d` | no |
| `multi_resolution_patch` | one `W_k` per resolution, resolution embeddings, LayerNorm | `[B, Σ T/P_k, d]` | `O(B·d·C·T·K)`; params `Σ CP_k d + Kd + 3d` | no |
| `learned_tokens` | projection, codebook `E (K×d)`, LayerNorm | `[B, T/P, d]` + codes | `+ O(B·(T/P)·K·d)` search | yes |
| `residual_vq` | projection, `S` codebooks, LayerNorm | `[B, T/P, d]` + codes `[.., S]` | `+ O(B·(T/P)·S·K·d)`; effective vocabulary `K^S` | yes |
| `grouped_embeddings` | one `W_m` per non-empty group, LayerNorm | `[B, T/P, d]` | same MACs as dense; **fewer** params (block-diagonal) | no |
| `mask_aware` | projection over `2C` channels, absent embedding `A (C×d)`, LayerNorm | `[B, T/P, d]` + validity | `O(B·(T/P)·2CP·d)`; params `2CPd + Cd + 3d` | no |
| `hybrid` | projection, codebook, fusion `W_f (d×2d)`, LayerNorm | `[B, T/P, d]` + codes | `+ O(B·(T/P)·2d²)` | yes |

### 2.1 On "parameter-free"

Some sub-steps here are genuinely parameter-free and are described that way
**about themselves only**:

- Patch *folding* — the reshape grouping `P` consecutive timesteps — has no
  parameters. The projection applied to the folded result has `CPd + d`.
- Instance normalisation as implemented in `encoder.normalise_window` subtracts a
  mean and divides by a standard deviation with no learned affine, so that
  sub-step is parameter-free. The encoder containing it is not.

Every count quoted above is for the whole candidate, and
`test_the_declared_parameter_count_is_the_count_measured` measures it from the
built module rather than trusting the formula — so a mismatch between claim and
reality is a test failure.

### 2.2 On prior work

Patch-based tokenisation of time series, vector quantisation with a
straight-through estimator, and residual vector quantisation are **published,
general techniques with a substantial literature**. Olympus claims no novelty in
any of them, and each candidate's `prior_art` field says which family it belongs
to; `test_every_candidate_states_its_relationship_to_prior_work` asserts the word
appears.

What *is* claimed is independent implementation: written against Olympus's own
contracts and channel schema, initialised from a seeded Olympus RNG, trained only
on Olympus datasets, and reading no external weight file, codebook or hub
identifier. Two structural tests enforce it —
`test_no_native_module_imports_a_kronos_source_module` and
`test_no_native_module_reads_an_external_weight_or_vocabulary_file`.

### 2.3 Stated limitations, in each candidate's own record

The ones that would change a decision:

- **`multi_resolution_patch`** concatenates several time orders, so its positions
  are **not one sequence**. A causal convolutional trunk may not be applied
  across the join. It declares `sequential=False` for exactly this reason, and
  that is the main argument against it despite its winning the reconstruction
  comparison below.
- **`learned_tokens`** imposes a hard error floor: no move finer than a codebook
  cell is representable, and a risk engine reasoning in basis points is
  downstream. Codebook collapse is invisible in the loss, which is why
  `utilisation()` exists.
- **`grouped_embeddings`** cannot represent an interaction between a price and a
  volume channel within a patch — the block-diagonal structure forbids it. And in
  this environment **two of its four declared groups are empty**, because their
  channels are `NOT_INGESTED`, so it is being evaluated at a fraction of its
  intended width.
- **`mask_aware`** doubles the input width for a benefit that is zero when
  nothing is missing. Its patch-level absence is the minimum over the patch, so
  one absent bar marks the whole patch absent — conservative, and it discards the
  partially-observed case.
- **`hybrid`** can learn to ignore its discrete branch entirely, becoming
  `continuous_patch` with extra cost, and nothing in the loss reports that it has
  happened.

## 3. Representation comparison — reconstruction, synthetic AR(1)

Reconstruction rather than forecasting, deliberately: a forecasting score
confounds the representation with the trunk, while reconstruction asks the one
question a representation is responsible for — *what did it keep?*

Same windows, same objective, same budget (30 epochs, seed 0, `d_model=16`,
`patch_len=4`, `codebook_size=16`, 682 windows from an AR(1) φ=0.97 series).

```
candidate                 params   pos    initial      final       gain   util    secs
--------------------------------------------------------------------------------------
multi_resolution_patch      2072    14   0.578627   0.000185   0.578442      -    1.69
mask_aware                   928     4   0.823603   0.000316   0.823287      -    0.85
hybrid                      1392     4   0.934777   0.000348   0.934429   0.62    1.11
grouped_embeddings           416     4   0.918529   0.000370   0.918159      -    1.24
continuous_patch             576     4   0.729491   0.000388   0.729103      -    0.57
residual_vq                 1088     4   0.519892   0.042301   0.477591   0.81    1.33
learned_tokens               832     4   0.510925   0.099502   0.411423   1.00    0.88
```

**Reading it honestly.** The ordering is not the conclusion.

- `multi_resolution_patch` wins on error and has **14 latent positions to
  everyone else's 4** — more than three times the capacity to carry the input
  through. It also breaks the single time order the causal trunk needs. It is not
  obviously the right choice; it is the largest one.
- `grouped_embeddings` reaches within 5% of `continuous_patch`'s error with
  **72% of the parameters**, which is the block-diagonal saving its complexity
  note predicts.
- The two quantised candidates pay exactly the floor they document:
  `learned_tokens` plateaus at 0.0995 — **256× the continuous error** — and
  `residual_vq` cuts that to 0.0423, a 2.4× improvement from one extra stage.
  `test_the_quantised_candidates_pay_the_error_floor_they_document` asserts both
  relationships, so the claim is checked rather than narrated.
- `learned_tokens` shows utilisation 1.00 and `residual_vq` 0.81 — the latter is
  the **minimum across stages**, so the second codebook is partly collapsed,
  which is the failure mode its record warns about.

**No selection has been made.** These are reconstruction results on a synthetic
linear process. Choosing a production representation on them would be choosing on
the fiction; `continuous_patch` remains what `neural.py` uses, on the parsimony
argument, and that decision is open.

## 4. The nine baselines

A complex model earns its place by beating simple alternatives **on the same
data, the same splits, the same costs and the same metrics**. Each clause is a
way a comparison is usually rigged, and `benchmark.py` owns all four so no model
can quietly get a different one.

| Baseline | Rule | Deps |
|---|---|---|
| `persistence` | Zero cumulative log return at every step | stdlib |
| `moving_average` | Mean recent log return, extrapolated | stdlib |
| `linear_regression` | Ridge regression on Olympus features, one solve per horizon step | stdlib |
| `autoregression` | AR(p) on log returns, iterated forward and cumulated | stdlib |
| `gradient_boosted_trees` | Least-squares boosting, hand-written depth-limited trees | stdlib |
| `recurrent` | Single-layer GRU with a linear head | torch |
| `temporal_transformer` | One causal self-attention block | torch |
| `volatility` | Zero drift, interval scaled by realised volatility | stdlib |
| `regime` | Drift and spread conditioned on Olympus's regime label | stdlib |

**Point forecasts become quantile forecasts the same way for all nine.** Fit the
point rule, take its residuals *on the training split only*, use their empirical
quantiles as the spread. So a baseline's interval is as good as its residuals
deserve, and a native model's advantage must come from conditioning its spread on
the input — which an empirical residual quantile cannot do.

Two baselines deliberately break that symmetry to make the comparison harder:
`volatility` scales its spread by the window's realised volatility, and `regime`
conditions both drift and spread on the regime label.

**A property worth knowing before reading any table.** A point forecast that is
the same constant for every window scores *identically* to persistence: shifting
every prediction by `c` shifts every residual by `-c`, and the empirical residual
quantiles shift it straight back. So a row matching persistence to six decimals
usually means the model degenerated. `RegimeBaseline` detects its own degeneracy
and says so in `BaselineFitReport.notes`; at a 33-bar lookback the regime
classifier has not warmed up and reports `unknown` for every window, which is
exactly that case.

**Two of nine need torch.** `available_baselines()` reports which can run, and
`BenchmarkReport.unavailable` records the ones that could not — so an
installation without torch reports seven results rather than silently comparing
against fewer opponents.

**`gradient_boosted_trees` is hand-written.** Olympus ships three required
dependencies behind a CI guard (blocker B6); adding scikit-learn to acquire a
baseline would be a permanent dependency bought for a comparison. Split
candidates are sample quantiles, so the fit is `O(rows · features · candidates)`.

## 5. The harness

| Clause | Mechanism |
|---|---|
| Same data and split | `run_benchmark` hands the identical `train` to every `fit` and the identical `test` to every scoring pass. `test_every_model_is_scored_on_the_same_windows` checks it |
| Same costs | `CostModel` subtracts a round trip; a predicted move smaller than it is **not a trade** |
| Same metrics | One `score_model` for every model. Pinball on the declared grid, median MAE, interval coverage, directional accuracy, abstention rate, net and gross return |
| Abstention | Not scored as a wrong answer, but `abstention_rate` sits beside every score and `compare_scored` **intersects** window sets rather than zipping them |
| Significance | Paired bootstrap on the windows both models answered |

**The verdict rests on pinball loss alone.** A model that improves absolute error
while degrading the distribution has not improved the forecast, and letting three
metrics vote would let it claim two out of three.
`test_the_verdict_rests_on_the_proper_scoring_rule_alone` pins that.

**A model that fails to fit is recorded, not fatal.** A benchmark that stops at
the first broken opponent reports nothing, and the remaining comparisons are
still valid. `BenchmarkReport.failures` carries them and `table()` prints them.

**The harness decides nothing.** `run_benchmark` returns numbers. Promotion still
lives in `champion.py` behind `capabilities.promote()`, which requires a human.

## 6. Benchmark record — synthetic, reproducible

Reproduce with `python scripts/native_benchmark.py`. 1,200 bars, lookback 33, horizon 3,
train/validation/test = 699/215/181, costs 2bp spread + 1bp fee per side.

### 6.1 AR(1), φ=0.97, σ=0.001 — a **linear** process

```
gradient_boosted_trees       855     181   0.00   0.001022   0.002864   0.785  0.884   0.006083    better

olympus_native              1679     181   0.00   0.001744   0.004831   1.000  0.840   0.006036    better
temporal_transformer        2594     181   0.00   0.001761   0.004508   0.895  0.840   0.005725    better
recurrent                   1122     181   0.00   0.001781   0.004483   0.890  0.823   0.005720    better
volatility                    16     181   0.00   0.002606   0.007591   0.845  0.481  -0.001827    better

```

**The native network came fifth, beaten by a 19-parameter AR(3) fit by 1.9×.**
That is the correct result — the generating process is linear by construction, so
a linear model should win — and it is the single most useful thing this benchmark
has produced. `test_a_linear_process_is_won_by_the_linear_models` asserts it, so
the suite is capable of reporting that the network lost.

Two further readings:

- **The native model's intervals are badly calibrated.** Coverage 1.000 against a
  nominal 0.80: every observation fell inside its 10–90 band, so the band is far
  too wide. Its pinball loss is being carried by an over-cautious spread rather
  than by a sharp median. Nothing about this is visible in its training loss.
- **`regime` is degenerate here** and reports so, for the reason in §4.
  `volatility` beats persistence purely on its conditional spread — which is the
  precise skill it was included to isolate.

**`winners: (none)`.** On a series with no structure, nothing beat persistence and
the three largest models were significantly *worse*. This is the control that
makes §6.1 worth reading: a harness that reported an edge here would be measuring
something other than skill, and every "better" verdict above would be
meaningless.

Note also that costs turn nine of ten models' gross edge into a **negative** net
return on the random walk, while persistence — which never trades, because its
predicted move never exceeds the round trip — nets exactly zero. That is the cost
model doing its job.

## 7. What these results do and do not license

**They license:** the pipeline learns; the harness distinguishes structure from
noise; the quantised representations pay the floor they document; the block-
diagonal grouping saves the parameters it claims; the native network is currently
*worse* than an autoregressive fit on a linear process and its intervals are
badly calibrated.

**They do not license** any statement about markets. Both series were generated
by `scripts/native_benchmark.py` and by
`tests/test_trading_native_baselines.py`. A model that loses to AR(3) on an AR(1)
process has told you about AR(1), not about whether it would lose on real bars.

**Olympus still owns no trained market model.** Gates G10–G14 remain blocked on
B1, and §6 does not touch any of them.
