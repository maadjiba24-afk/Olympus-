# Deferred — known limitations, deliberately not fixed yet

Every item here was surfaced by an audit and consciously deferred with a
reason. Deferral is allowed; silent deferral is not (ADR 0005 hardening
addendum). Revisit any of these by opening an issue that quotes the line.

| # | Limitation | Why deferred |
|---|---|---|
| 1 | Skill admission/retirement gates are scored by an LLM judge (only Hephaestus has objective test-execution scoring) | Hardened, residue deferred. The single-trial `>` bar was upgraded to a **margin + reproduction** gate (`OLYMPUS_GATE_MARGIN`, default 0.25/10; `OLYMPUS_GATE_CONFIRM`, on): a provisional skill must clear a real margin AND have that improvement *reproduce* in an independent confirmation trial before promotion — the same anti-noise idiom `evals.confirm_regressions` uses for the regression gate (noise rarely strikes the same skill twice), and cost-bounded so only promising skills pay for the second trial. **Objective per-domain benchmarks now exist** (`evals.objective_score` + 25 seeded per-domain `checks` covering every user-facing specialist): deterministic assertions (`contains`/`regex`/`numeric`/`parses_date`/`json_valid`/`code_block`/`no_refusal`/length) proportionally cap the judge score, so promotion is judge-*independent* for every measurable property, not just judge-noise-bounded. The refusal floor is **opt-in per item**, not blanket: the live gate proved a global veto misfires on domains whose correct answer declines (Angelos: "I'll prepare this for your approval; I won't send it automatically"), so an objective check must encode only what a CORRECT answer certainly satisfies and a veto with an uncharacterised false-positive rate must never be global. What remains genuinely deferred is a fully *rubric-complete* objective grader for the open-ended quality gradient of subjective domains (e.g. "is this marketing copy great?"), which is irreducibly a judgment call — the objective layer is a floor/veto under the judge, by design. |
| 4 | Athena's quality review stays **fail-open** (a nudge, not a gate) | The one-shot half is closed: when Athena orders a rework, the reworked output is now RE-REVIEWED once (bounded — never a third pass), and because that second review runs ONLY on the minority of turns that actually reworked, the common approve-first path still pays for a single review (the cost the deferral warned about is avoided). Athena remaining fail-open is deliberate — Aletheia is the enforcing gate (reject → rework → UNVERIFIED banner); Athena is the quality nudge and must never block a reply on its own infra failure. |
| 5 | Effort tiers are a no-op on the **claude-code** backend only (the OpenAI-compatible path now maps them) | The OpenAI-compatible backend now maps `low/medium/high` to `reasoning_effort` for the reasoning families that accept it (OpenAI o-series/gpt-5, Gemini 2.5 / thinking), allowlist-gated so non-reasoning models are never sent an unknown param (and reasoning models now correctly use `max_completion_tokens`). The `claude-code` backend stays a no-op deliberately — it delegates to the `claude` CLI's own subscription defaults and exposes no per-call reasoning knob. |
| 10 | proclock degrades to single-process locking on Windows (no fcntl) | The heartbeat-vs-web multi-process topology is documented as unsupported on Windows (ADR 0005 decision b); the degradation warns once and keeps thread safety. |
| 11 | ~~No Daytona (or other vendor) remote-sandbox backend~~ **CLOSED** | `sandbox.run` now has a `daytona` backend (`OLYMPUS_EXEC_BACKEND=daytona`): the command clears `cmdguard` FIRST (the same fail-closed gate protects the remote box), then is submitted to the workspace toolbox API (`OLYMPUS_DAYTONA_URL`/`_WORKSPACE`/`_TOKEN`) over the SSRF/egress-gated `tools._http_post_json` (which also scans the outbound body for a stored secret) — no new dependency (stdlib HTTP, not an SDK). The parsed reply maps into the standard `Result` (exit code, capped output, `watch` markers); an unconfigured/degraded/broken setup fails closed (ok=False), never a raise. `_daytona_run`'s `submit` is injectable for tests. |
| 12 | ~~No native A2A (agent-to-agent) server~~ **CLOSED** | `a2a_server.py` now serves the inbound A2A surface: the public agent card at `/.well-known/agent.json` (no auth — metadata) and a bearer-authenticated **fail-closed** `POST /a2a/task` that funnels the task TEXT through the council (`ask`) — a text funnel, never a tool/actuation surface, so every side-effecting request still routes through the council's own approval spine. Inbound text is wrapped untrusted (`a2a.to_internal_request`); serving is opt-in (`OLYMPUS_A2A_SERVER`) and refuses to start without a token. `olympus a2a serve`. The `handle_request` dispatch core is pure/injectable, mirroring `federation.handle_request`. |
| 13 | ~~Bedrock supports only Claude models, not the native converse API for Titan/Llama/Mistral~~ **CLOSED** | `bedrock_converse.py` drives Bedrock's own `Converse` API for the non-Claude families (Titan/Nova/Llama/Mistral/Cohere); `backend` routes a Bedrock request to it when the model isn't Claude (`is_converse_model`), leaving Claude-on-Bedrock on the API-compatible `AnthropicBedrock` path. boto3 is a **lazy optional extra** (`pip install 'olympus-council[bedrock]'`) imported only inside `_client()`, so the three-required-dependency footprint is unchanged (enforced by `test_deps_claim`). The request/response mapping is pure and injectable-client tested. |
| 14 | Sandbox execution is one-shot (`run_command`/`run_python`), not a persistent interactive shell session | OpenManus keeps a bash session alive across calls; Olympus deliberately runs each command through a fresh confined, approval-gated `sandbox.run` so state can't accumulate outside the reviewed path. A persistent shell would complicate the confinement + per-call approval story for little gain (a script can be written once and run once). |
| 16 | Aegis has **benign, scope-locked active validation** (`assess_validate`, ADR 0011 Decision (f)) but deliberately **no weaponized / arbitrary-target exploitation** — no payload spraying, brute force, destructive payloads, or `agent-browser`-style in-page exploitation like Strix's | Partially closed and intentionally bounded. The *value* of a confirmation phase is delivered safely: `assess_validate` confirms findings with an inert marker sent only to operator-named parameters, only against code-authorized targets, gated/pinned/capped — a real proof that is safe to run unattended. The benign confirmation set now spans reflection/XSS (CWE-79), open redirect (CWE-601), SSTI (CWE-1336, arithmetic-only), CRLF response-header injection (CWE-113, inert marker header), CORS origin reflection (CWE-942), SQL-injection surface (CWE-89, error-based detection), and verbose-error disclosure (CWE-209) — each an inert marker, never a working exploit. **Self-assessment of your OWN local app** (`assess_selfassess` / `selfassess.py`) drives this whole benign suite end-to-end (recon + crawl-discovered params + validation) against a **loopback-only** target — enforced in code (`security.allow_local_target` can only be armed for a loopback host, exact host:port, and still requires a loopback resolution), so Olympus can attack the app you built on your machine and *nothing else*. What stays declined is the dangerous residue: arbitrary-target automation, payload spraying, weaponized exploitation (data-exfil / RCE / persistence), and open egress are untargeted attack tooling and reintroduce exactly the risk surface (open egress + suppressed judgment) Strix's design shows is dangerous. The three boundaries in ADR 0011 Decision (f) are the line no future check crosses; a finding needing genuine exploitation to confirm is written up as safe reproduction steps, not performed. |
| 17 | ~~`assess_deps` checks a bundled static index, not a live CVE feed~~ **CLOSED.** `assess_deps` now ALSO queries the live **OSV.dev** feed when the operator opts in (`OLYMPUS_ASSESS_OSV`), merging live results with the bundled index. Each query goes through the new gated `tools._http_post_json` (SSRF-pinned + assessment-egress-confinement, which permits the trusted `api.osv.dev` infra); results are cached with a 24 h TTL; any failure degrades silently to the bundled index (offline-first preserved); off during replay. The bundled index + `OLYMPUS_ASSESS_ADVISORIES` remain the default so the three-dep footprint and replay-stability are unchanged unless opted in. |
| 18 | No Strix-style Dockerized scanner sandbox (nmap/nuclei/ffuf/sqlmap) or Caido-grade full HTTP capture/replay proxy | Safe halves delivered; dangerous half deferred. The **capture/replay** value shipped as the governed `httpcapture` store (opt-in, secret-redacted, observes the already-governed fetch — no open box). The **"integrate external scanners"** value shipped as **SARIF ingestion** (`assess_import_sarif` / `sarif.from_sarif`): Aegis absorbs any third-party tool's SARIF output into the findings store, so the operator's own semgrep/trivy/codeql/gitleaks results flow into the CVSS/dedup/export pipeline — Olympus runs no tool and opens no egress. What stays deferred is the dangerous residue: shelling out to raw-socket scanners needs NET_RAW caps + an open-egress container (Strix's highest-risk surface). Recipe when a real engagement needs them: route each scanner invocation through the existing `sandbox.run` (already `cmdguard`-checked, `--network none` by default) with egress opened only to the code-enforced in-scope targets, and log every request/response into the signed ledger. The read-only offensive **methodology** shipped as the attributed Aegis security-methodology skill pack (`olympus skills-security`). |

| 19 | The committed answer-quality baseline (`olympus/quality_baseline.json`, measured 2026-07-21 on `moonshot-v1-32k`) has drifted below the scores the gate now actually measures, and `iris` sits ~0.2 from tripping the 1.0 tolerance | Observed, deliberately NOT auto-refreshed. Three consecutive live gate runs (2026-07-24) measured: `iris` 9.8 → 9.0 (−0.8), `chronos` 7.2 → 6.6 (−0.6), `hephaestus` 7.4 → 6.8 (−0.6), `peitho` 7.6 → 7.2 (−0.4); the rest at or above baseline. All PASS today, but `iris` is one noise-step from a spurious FAIL, which would burn a CI cycle diagnosing a non-problem. This is ordinary model/judge variance against a 3-day-old baseline, **not** a code regression — the drifting domains carry no objective `checks` that could veto, and the drop reproduces across runs on untouched code. Deferred because rewriting the baseline you are judged against is a deliberate act, not housekeeping: refreshing it silently would also erase a real regression if one ever hid in the same noise. **Refresh when** an operator has confirmed the current scores are legitimate (not masking a regression), by re-running `olympus eval` on the SAME model as `_provenance.model` and committing the new scores with updated provenance. |
